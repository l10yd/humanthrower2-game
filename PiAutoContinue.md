# Автопродолжение pi

## Новое окно

Запустите `StartPiAuto.bat` двойным щелчком и задайте агенту первую задачу.
По умолчанию после 30 секунд непрерывного простоя отправляется пользовательское
сообщение **«продолжаем»**. В пустой новой сессии автоматика ждёт первой задачи.
Обычный `StartPi.bat` остаётся без автоматической отправки.

Другой интервал (секунды, целое число от 5 до 86400):

```bat
StartPiAuto.bat 60
```

Для изменения значения при двойном щелчке отредактируйте в батнике:

```bat
set "PI_AUTO_CONTINUE_SECONDS=30"
```

## Уже открытые окна этого проекта

В **каждом нужном окне** pi выполните отдельно:

```text
/reload
/autocontinue on 30
```

Проект должен быть доверенным, чтобы pi загрузил `.pi/extensions/auto-continue.ts`.
Если команда после `/reload` не появилась, проверьте доверие через `/trust`
и ещё раз выполните `/reload`. Настройки пользователя и остальных проектов не меняются.

## Управление

```text
/autocontinue on 60
/autocontinue off
/autocontinue status
```

В статусной строке отображается `AUTO 30s` или `AUTO off`.
Команда `off` прекращает новые автоотправки, но не отменяет уже начатую работу.
Остановить текущую работу можно Escape — это также выключает автоматику.
Окончательная ошибка агента, включая **`exceeded token rate limit`** и
**`Retry failed after 3 attempts`**, больше не выключает режим: после завершения
встроенных повторных попыток расширение ждёт обычный интервал простоя
(по умолчанию **30 секунд**) и снова отправляет «продолжаем».
При последовательных ошибках пауза не увеличивается: каждая новая попытка
использует тот же настроенный интервал, без дополнительных задержек.
Нажатия клавиш и блокирующие состояния сбрасывают отсчёт непрерывного простоя,
в том числе перед повтором. `/autocontinue off` отменяет ожидающий повтор;
явное `on` начинает отсчёт заново. Если режим выключен, ошибка его не включает.
После ручной остановки включить снова можно командой `on`.
После `/reload`, смены сессии или перезапуска состояние не сохраняется:
обычное окно требует повторного `on`, запуск с флагом `--auto-continue`
вновь включает режим, но ждёт первой завершённой задачи.

## Как это работает

Это не OCR и не глобальная эмуляция клавиатуры. Расширение внутри каждого pi
раз в секунду проверяет реальное состояние агента и отправляет сообщение через
`pi.sendUserMessage()`, только если агент простаивает заданное число секунд.
Оно не требует фокуса окна, работает и в свёрнутом окне, не пишет в другие приложения.
Уже работающие окна без расширения нельзя подключить одним внешним батником:
им нужен `/reload` и явное включение в каждом окне.

Автоотправка не происходит во время работы, повторных попыток, сжатия контекста,
ожидания диалога расширения, при наличии очереди сообщений или непустого редактора.
Нажатия клавиш сбрасывают таймер простоя. Расширение не запускает цикл в print,
JSON или RPC режимах. Оно не определяет, что задача выполнена или агент задал
вопрос обычным текстом: пока режим включён, сообщение повторяется после каждого
успешного завершения работы или окончательной ошибки — с одинаковой паузой.
Сам лимит провайдера расширение не снимает: оно повторяет запросы, пока сервис
снова не начнёт их принимать. `StartPiAuto.bat` уже подключает нужное расширение,
поэтому менять батник для этого поведения не требуется.

**Внимание:** режим может бесконечно продолжать работу, расходовать токены
и изменять файлы. Он не делает действия агента безопасными и не ограничивает
доступные инструменты. Для остановки используйте `/autocontinue off` или Escape
во время работы. Несколько агентов в одной папке могут конфликтовать при записи файлов.
